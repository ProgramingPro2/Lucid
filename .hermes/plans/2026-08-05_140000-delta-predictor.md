# Delta-Space Forward JEPA Predictor (the "oscillator" fix)

> **For Hermes:** Work task-by-task with a real measurement per stage. Reuse SQLite resumable checkpointing + GPU gate. Fresh artifacts dir (no destructive deletes).

**Goal:** Replace the exact-next-vector predictor (built to fail at the 0.05 wall) with a **delta predictor** — predict the *direction of change* in concept space, not the destination. Empirically proven learnable: a ridge on delta→delta hits **0.46 test cosine** vs the 0.05 exact-next wall and vs persistence (-0.49) / reversal (+0.49) baselines. This is the first real forward signal found in the project.

**Why it works (plain English):** text *oscillates* — the next sentence bounces back from the current one. You can't predict the exact next point of a pendulum, but you *can* predict which way it's swinging. The delta predictor learns the swing pattern.

## The key unit test (this must pass first)

From `experiments/test_delta_verify.py` (already reproduced, committed, 5-fold):
```
5-fold ridge delta→delta: test cos=0.464
  persistence baseline (predict same)  = -0.49
  reversal baseline    (predict flip)  = +0.49
  random                               =  0.00
```
The *real trained model* must beat the persistence/reversal/random baselines on held-out data by a wide margin — if it doesn't, the delta signal isn't surviving the stronger model.

## Task 1: Delta sequence dataset

**Objective:** windows of concept *deltas* → the next delta. Mirrors `ConceptSequenceDataset` but computes `d[i] = z[i+1] - z[i]` (normalized) so the model reads the *oscillation*, not absolute position.

**Files:**
- Create: `src/conceptpoc/data/delta_dataset.py`
- Reuse: `CachedCorpus` (`data/cache.py`)

**Step 1: The dataset**

```python
class DeltaSequenceDataset(Dataset):
    """Predict next change-direction from a window of prior change-directions."""
    def __init__(self, corpus, context_len=16, abs_start=False):
        vectors = corpus.vectors           # (N, dim), doc-contiguous
        self.context_len = context_len
        self._windows = []
        for start, end in corpus.doc_slices():
            n = end - start
            if n < 4:                       # need deltas + a target
                continue
            # deltas[i] = vectors[start+i+1] - vectors[start+i]
            # predict deltas[t] from deltas[t-context:t]
            for t in range(start + 3, end):
                d = vectors[t] - vectors[t-1]
                ctx_end = t                             # index of current (before next delta)
                ctx = (vectors[start+1:ctx_end] - vectors[start:ctx_end-1])  # deltas before target
                ctx = ctx[-context_len:]
                if len(ctx) < 2:
                    continue
                self._windows.append((start, ctx_end, ctx, d))

    def __getitem__(self, idx):
        _, _, ctx, d = self._windows[idx]   # returns (ctx_deltas, target_delta)
        return ctx, d
```

**Step 2:** Reuse `collate_sequences` (it right-pads ctx, returns target stack) — target is now the delta.

**Step 3: Test on a tiny corpus** (`tests/test_delta_dataset.py`): shapes correct, deltas finite, and a trivial 2-step trajectory reproduces a delta.

**Step 4: Commit**

## Task 2: Delta predictor model (reuse trunk, change normalization)

**Objective:** same causal transformer trunk; the difference is *what* it predicts and *how* the output is used. Keep `ConceptPredictor`'s architecture; add a `DeltaPredictor` wrapper.

**Files:**
- Create: `src/conceptpoc/predictor/delta_model.py`

**Step 1: DeltaPredictor**

```python
class DeltaPredictor(ConceptPredictor):
    """Predicts the NEXT CHANGE DIRECTION from a window of prior deltas.
    Trunk identical; difference is semantic (input/output are deltas)."""
    # inherits encode_context/forward; we just train on deltas & normalize
    # the target the same way. No new weights needed -> reuse as-is.
```

Actually — the trunk expects L2-normalized "concept vectors" on the unit sphere. Deltas are NOT unit spheres. Two choices:
- (a) train on *normalized* deltas (direction only, ignores magnitude) — matches the experiment.
- (b) train on raw deltas with MSE+cosine (magnitude matters).

Go with **(a) normalized deltas** — the experiment normalized (`normalize(d)`), and direction is the learnable part. `DeltaPredictor.forward` outputs normalized directions already.

**Step 2: Test** (`tests/test_delta_model.py`): a tiny `DeltaPredictor` reduces cosine loss on a synthetic oscillating trajectory (predict-flip → near-perfect after a few steps).

# seed context -> concept vectors
zs = codec.encode(seed_sents)
for step:
    d = zs[-1] - zs[-2]                      # last delta

## Decision gates

- **Task 3:** held-out delta-cosine must be clearly > 0 (and ideally > 0.15). If ~0/negative → the delta signal doesn't generalize to the full model → honest negative, stop.
- **Task 5:** delta generation must visibly reduce topic drift vs exact-next. If writer fluency is lost (deltas push off-manifold), normalize-then-decode and possibly re-run decoder-robust on delta-perturbed vectors.

## Risks

| Risk | Mitigation |
|------|-----------|
| Deltas push vectors off the unit sphere → writer garbles | normalize z_next before decode; re-run decoder-robust on delta-perturbed vectors |
| Model learns reversal-only (trivial) | compare vs reversal baseline explicitly; need *beyond*-reversal signal |
| Delta magnitude ignored (direction-only) | direction is the proven signal; keep normalized |
| Oscillation doesn't map to topic stickiness | gate on Task-5 seq-cos and manual read |
